# 🎙️🌐 โหมดประชุม & โหมดแปลภาษา

สองโหมดนี้ใช้โมเดล Live **เฉพาะทาง** ซึ่งไม่ใช่ผู้ช่วยสนทนา จึงแยก session / แยกหน้าจอ / แยกปุ่มออกจากห้องแชทและโหมดผู้ช่วยทั้งหมด
(สร้าง 2026-09-16 — อ้างอิงความสามารถจากเอกสาร Gemini ทางการ)

## ขอบเขตความสามารถจริง

| หัวข้อ | โหมดประชุม `gemini-3.5-transcribe-live` | โหมดแปลภาษา `gemini-3.5-live-translate-preview` |
|---|---|---|
| หน้าที่ | ถอดเสียงเป็นข้อความเรียลไทม์ | แปลเสียง→เสียง แบบสตรีมต่อเนื่อง |
| ภาษา | 85+ ภาษา ตรวจเอง สลับภาษากลางประโยคได้ | 70+ ภาษา (เลือกภาษาปลายทาง ต้นทางตรวจเอง) |
| ผลลัพธ์ | ข้อความ (TEXT) | เสียงคำแปล + ข้อความทั้งต้นทางและคำแปล |
| **แยกเสียงผู้พูด (diarization)** | ❌ **ไม่รองรับในโหมดสด** (รองรับเฉพาะโหมดประมวลผลไฟล์ สูงสุด 8 คน) | ❌ |
| Timestamp ระดับคำ | ❌ ไม่รองรับในโหมดสด | ❌ |
| คำศัพท์เฉพาะ (custom vocabulary) | ✅ สูงสุด 1,000 คำ (ดีที่สุด ~100 คำ) | ❌ |
| จัดรูปแบบอัตโนมัติ | ✅ โหมด `SMART` ตัดคำฟุ่มเฟือย จัดวรรคตอน/ย่อหน้า | — |
| Tool / คำสั่งระบบ | ❌ | ❌ (เป็นล่ามล้วน) |
| ความยาวต่อ session | **10 นาที** → แอปต่อ session ใหม่ให้เองทุก 8 นาที | ตามลิมิต Live ปกติ |
| โควตา free tier | RPM/RPD ไม่จำกัด, TPM 20K | RPM/RPD ไม่จำกัด, TPM 20K |

> **หมายเหตุสำคัญ**: ถ้าต้องการ "ใครพูดอะไร" จริงๆ ต้องบันทึกไฟล์เสียงแล้วส่งเข้าโมเดล `gemini-3.5-transcribe` (โหมดไฟล์) ภายหลัง ซึ่งรองรับ diarization สูงสุด 8 คน (โควตา free tier 3 RPM / 25 RPD) — ยังไม่ได้ทำในรอบนี้

## สถาปัตยกรรม
- `data/LiveSpecialistService.kt` — WebSocket session ของทั้งสองโหมด (setup แยกกัน, ต่อ session ใหม่อัตโนมัติสำหรับโหมดประชุม)
- `controller/SpecialistSessionController.kt` — ไมค์ของตัวเอง, รวมข้อความเป็นย่อหน้า, จับเวลา, พัก/หยุด, สรุปด้วยโมเดลแชท, ส่งผลเข้าห้องแชท
- `ui/screen/MeetingScreen.kt`, `ui/screen/TranslateScreen.kt` — คนละหน้ากับแชท
- ปุ่มเข้าใช้งานอยู่ใน **Speed Dial ของปุ่มแนบไฟล์** ในแถบพิมพ์ข้อความ: กดแล้วกางเป็น 3 ไอคอนลอยขึ้นด้านบน (แปลภาษา / บันทึกการประชุม / แนบไฟล์) ปุ่มหลักเป็นไอคอนจุดสามจุดแนวตั้งตอนหุบ และเปลี่ยนเป็นกากบาทตอนกาง ปุ่มย่อยเป็นไอคอนล้วนไม่มีป้ายชื่อ และใช้ `Popup` จึงไม่ดันความกว้างของแถบพิมพ์ กดพื้นที่อื่นหรือกดกากบาทเพื่อหุบ (Popup แบบไม่ focusable ยิง `onDismissRequest` พร้อมปล่อยทัชทะลุไปโดนปุ่มหลัก จึงมีตัวกัน 300ms กันเมนูหุบแล้วกางใหม่ทันที)
- เปิดโหมดใดโหมดหนึ่ง → ปิด Live session ของผู้ช่วยอัตโนมัติ (กันแย่งไมค์)

## UI หน้าประชุม
- ข้อความถอดเสียงแบบเรียลไทม์ เลื่อนตามอัตโนมัติ แบ่งเป็นย่อหน้าพร้อมเวลาเริ่มของแต่ละย่อหน้า
- แถบสถานะ: กำลังเชื่อมต่อ / กำลังฟัง / พักอยู่ / ต่อ session ใหม่ / ขัดข้อง พร้อมจุดไฟกระพริบตามระดับเสียง
- ตัวจับเวลารวม
- ปุ่ม: **เริ่มบันทึก** → **พัก / พูดต่อ** → **หยุดและสรุป** (+ ปุ่มปิด)
- กดหยุด → สรุปด้วย `flash-lite` เป็น markdown (สรุปย่อ / ประเด็นสำคัญ / สิ่งที่ต้องทำต่อ / คำถามค้าง) แล้วส่งเข้าห้องแชทพร้อมบันทึกคำต่อคำ

## UI หน้าแปลภาษา
- เลือกภาษาปลายทางจากปุ่มลัด 14 ภาษาที่ใช้บ่อย (โมเดลรองรับ 70+)
- สวิตช์ "พูดตามเมื่อผู้พูดใช้ภาษาปลายทางอยู่แล้ว" (`echoTargetLanguage`)
- แสดงคู่ข้อความ: บรรทัด "ได้ยิน" (ต้นทาง) และ "คำแปล" (เน้นสี) พร้อมเล่นเสียงคำแปล
- ปุ่ม: **เริ่มแปล** → **พัก / แปลต่อ** → **หยุด** (+ ปุ่มปิด) — หยุดแล้วบันทึกบทแปลเข้าห้องแชท


## ถาม AI ระหว่างประชุม (2026-09-16)

โมเดลถอดเสียงไม่ได้ "คิด" หรือ "จำ" อะไรเลย — แปลงเสียงเป็นข้อความอย่างเดียว และ session ผู้ช่วยก็อยู่คนละเส้น
ดังนั้นถ้าไม่แนบบริบทไปด้วย AI จะไม่รู้ว่าที่ประชุมคุยอะไรกันมา

วิธีที่ใช้:
- ช่องถามใต้บทประชุม → `SpecialistSessionController.askDuringSession(question)`
- ระบบส่ง **บทประชุมที่ถอดได้จนถึงวินาทีนั้น** ไปพร้อมคำถาม (จำกัด 20,000 ตัวอักษรท้ายสุด ซึ่งคือช่วงที่กำลังคุยกันอยู่) ให้โมเดลแชท `flash-lite` (context 1M)
- prompt สั่งให้ยึดบริบทจากบทประชุมก่อน และถ้าบทประชุมไม่มีข้อมูลให้บอกตรงๆ ว่ายังไม่ได้พูดถึง แล้วค่อยแนะนำทั่วไปสั้นๆ
- คำตอบแสดงเป็นการ์ดสีม่วงในบทประชุม (kind = `ASSISTANT`) **ไม่อ่านออกเสียง** เพราะไมค์กำลังอัดอยู่ ถ้าพูดออกลำโพงจะถูกถอดกลับเข้าบทประชุมเอง
- ทั้งคำถามและคำตอบติดป้าย `[AI]` ในบันทึกที่ส่งเข้าห้องแชท แยกจากคำพูดจริงในห้องประชุม
- การถาม 1 ครั้ง = 1 request จากโควตาแชท (flash-lite 1,000 ครั้ง/วัน) ส่วนการถอดเสียงไม่กินโควตารายวัน

ตัวอย่างที่ตั้งใจให้ทำงาน: ประชุมเรื่องอาคาร 4 ชั้น คุยถึงปั๊มน้ำ → ถาม "ปั๊มขนาดเท่าไรที่เหมาะสม" → AI เห็นบทประชุมทั้งหมดจึงตอบโดยอ้างอิงว่าเป็นอาคาร 4 ชั้นและบริบทที่คุยกันไปแล้ว


## หน้าประชุมแบ่งเป็น 2 ส่วน + ถามด้วยเสียง (2026-09-16)

```
┌──────────────────────────────┐
│ 🎙️ บันทึกการประชุม     12:34 │  ← สถานะ + เวลารวม
│ ● กำลังฟังและถอดเสียง         │
├──────────────────────────────┤
│ บทประชุม                      │  ← ส่วนบน (สัดส่วน 1.5)
│ 14:05:12 ...                  │     เฉพาะเสียงในห้อง
│ 14:05:40 ...                  │
├──────────────────────────────┤
│ ถามผู้ช่วย                    │  ← ส่วนล่าง (สัดส่วน 1)
│ คุณ: ปั๊มขนาดเท่าไร…          │     แชทถาม-ตอบ แยกจากบทประชุม
│ 🤖 ผู้ช่วย: …                 │
├──────────────────────────────┤
│ [ช่องพิมพ์…]        [ส่ง] [🎤] │
├──────────────────────────────┤
│ [❚❚ พัก] [■ หยุดและสรุป] [ปิด] │
└──────────────────────────────┘
```

**ถาม 2 ทาง**
| ทาง | เกิดอะไรขึ้น | โมเดลที่ตอบ |
|---|---|---|
| พิมพ์ + ปุ่มส่ง | ตอบเป็นข้อความในแชทด้านล่าง **บันทึกยังเดินต่อ** | `flash-lite` (1 request จากโควตาแชท) |
| ปุ่มไมค์ | **พักบันทึกอัตโนมัติ** → เปิด Live session ผู้ช่วย → ตอบเป็นเสียง คุยต่อได้เรื่อยๆ (ใช้ tool ได้ครบ) → กด "เลิกพัก" เพื่อกลับไปบันทึก | Live assistant (`gemini-3.8-live`) — RPD ไม่จำกัด |

- ทั้งสองทางแนบ "บทประชุมจนถึงวินาทีนั้น" ไปกับคำถามเสมอ (ท้ายสุด 20,000 ตัวอักษร) ผู้ช่วยจึงรู้บริบท เช่น รู้ว่ากำลังคุยเรื่องปั๊มน้ำของอาคาร 4 ชั้น
- ปุ่มไมค์ใช้ `startAssistantWithPrompt` → ตั้งคำถามเป็น greeting-on-ready ของ session ผู้ช่วย พอ READY ผู้ช่วยตอบทันที
- ระหว่างคุยด้วยเสียง โมเดลถอดเสียงถูกพัก (ส่ง `audioStreamEnd`) เสียงผู้ช่วยจึงไม่ถูกถอดปนเข้าบทประชุม
- คำตอบด้วยเสียงถูกบันทึกเป็นข้อความในแชทของหน้าประชุมด้วย (ดักจาก transcript ของผู้ช่วย)
- บันทึกที่ส่งเข้าห้องแชทหลักติดป้าย `[AI]` ให้แยกจากคำพูดจริงในห้องประชุม


## รีวิวตัวเอง + แก้เพิ่ม (2026-09-16 รอบตรวจ)

| # | ปัญหาที่เจอตอนรีวิว | แก้อย่างไร |
|---|---|---|
| 1 | **แย่งไมค์กันตอนถามด้วยเสียง** — `pause()` เดิมหยุดแค่ "การส่ง" แต่ยังถือ AudioRecord ไว้ ทำให้ session ผู้ช่วยได้ยินแต่ความเงียบ | `pause()` เรียก `stopRecording()` ปล่อยไมค์จริง และ `resume()` ยึดคืนด้วย `startMic()` |
| 2 | **กดปิดแล้วเปิดโหมดใหม่ทันทีไม่ทำงาน** — `start()` เห็น sessionJob เก่ายัง active แล้ว return เงียบๆ | เปลี่ยนเงื่อนไขเป็น `_mode.value != null` และให้ job ใหม่ `cancelAndJoin()` ของเก่าเสมอ |
| 3 | **โหมดแปล: คำแปลทั้งหมดต่อกันเป็นย่อหน้าเดียว** — `turnComplete` ปิดเฉพาะฝั่ง SOURCE | ปิดทั้ง SOURCE และ TRANSLATED (ทั้งตอนจบ turn และตอนต่อ session ใหม่) |
| 4 | **ถามด้วยเสียงหลายรอบ เก็บได้แค่คำตอบสุดท้าย** | ใช้ `liveTurnCompleteFlow` ปิดคำตอบทีละรอบ + บันทึกคำถามที่ผู้ใช้พูด (`liveUserTurnFinalFlow`) ลงแชทของหน้าประชุมด้วย |
| 5 | **นาฬิกากระโดด** — จับเวลาจาก wall clock ทำให้หลังเลิกพัก เวลาพุ่งรวมช่วงที่พักไปด้วย | สะสมเฉพาะช่วงที่บันทึกจริง (`accumulatedActiveMs` + `activeSinceMs`) |
| 6 | **ห้องเงียบยาวจะชนเพดาน 10 นาที** — เดิมเช็คเวลาต่อ session ใหม่เฉพาะตอนมีเฟรมเข้า | เพิ่ม watchdog ปิด session ที่ 8 นาทีเสมอแม้ไม่มีเสียง |
| 7 | **ข้อความซ้ำในโหมดประชุม** — รับทั้ง `inputTranscription` และ `modelTurn.text` | โหมดประชุมใช้ `inputTranscription` อย่างเดียว |
| 8 | **ไม่มี API key แล้วปุ่มค้างเป็น "กำลังทำงาน"** | `start()` เช็ค key ก่อน และแจ้งในหน้าจอแทนการเข้าโหมด |
| 9 | **แข่งกันเขียน segments** จากหลาย coroutine (transcript + ถาม-ตอบ) | เปลี่ยนเป็น `MutableStateFlow.update {}` (atomic) |
| 10 | **บริบทของคำถามปนคำตอบ AI เดิม** | ใช้ `meetingContext()` ที่กรองเฉพาะเสียงในห้อง |
| 11 | โหมดแปลเปิด echo แล้วเสี่ยงเสียงวนจากลำโพงเข้าไมค์ | ขึ้นคำเตือนให้ใช้หูฟังเมื่อเปิดสวิตช์ echo |

**ยังคงเหลือ (ยอมรับข้อจำกัด)**
- ต่อ session ใหม่ทุก 8 นาทีมีช่วงรอยต่อสั้นๆ (เสี้ยววินาที) ที่เสียงอาจหลุด — เป็นข้อจำกัดของเพดาน 10 นาทีต่อ session
- ระหว่างถามด้วยเสียง เสียงในห้องประชุมจะไม่ถูกบันทึก (ตั้งใจให้เป็นแบบนั้น เพื่อไม่ให้เสียงผู้ช่วยปนบทประชุม)
- ยังไม่มี pass แยกผู้พูดจากไฟล์เสียง (ผู้ใช้เลือกยังไม่ทำ)

## แท็บ "สรุปประชุม" (2026-09-17)

หน้าประชุมแบ่งเป็น 2 แท็บ

1. **ประชุม** — บทประชุมสด + แชทถามผู้ช่วย + ปุ่มควบคุม (เหมือนเดิม)
2. **สรุปประชุม** — รายการบันทึกที่เก็บไว้ในเครื่อง ชื่อรายการเป็น `วัน/เดือน/ปี-เวลา` แต่ละรายการมี 3 ปุ่ม
   - **▶ เล่น** — ให้ผู้ช่วย Live อ่านสรุปให้ฟัง (prompt สั่งห้ามอ่าน markdown ตามตัวอักษร) หยุดด้วยปุ่ม "■ หยุดอ่าน"
   - **อ่าน** — กางสรุป + บันทึกคำต่อคำในรายการนั้น (อยู่ใน LazyColumn เลื่อนได้)
   - **ลบ** — กดครั้งแรกเปลี่ยนเป็น "ยืนยันลบ?" กดซ้ำจึงลบจริง

**สรุปการประชุมไม่ถูกส่งเข้าห้องแชทหลักอีกแล้ว** — เก็บเป็นรายการในแท็บนี้แทน (โหมดแปลภาษายังส่งบันทึกเข้าแชทเหมือนเดิม)
พอกด "หยุดและสรุป" ระบบจะสลับไปแท็บสรุปและกางรายการล่าสุดให้เอง

ที่เก็บ: settings key `meeting_records_v1` เป็น JSON ของ `MeetingRecord` (id/title/durationMs/summary/transcript) เก็บสูงสุด 50 รายการ ใหม่สุดอยู่บน

### บั๊ก UI ที่แก้ไปพร้อมกัน
- กล่องสรุปเดิมแทรกอยู่ระหว่างแชทกับปุ่มควบคุมโดยไม่มีความสูงจำกัด → ดันปุ่มตกจอ เลื่อนอ่านไม่ได้ และค้างอยู่จนปิดแอป ตอนนี้ย้ายไปแท็บสรุปทั้งหมด เหลือแค่บรรทัด "กำลังสรุปการประชุม…" ระหว่างรอ
