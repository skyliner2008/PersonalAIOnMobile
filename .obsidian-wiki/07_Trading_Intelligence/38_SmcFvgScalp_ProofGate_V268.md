# V26.8 SMC FVG Scalp Proof Gate

Date: 2026-05-18

## Problem

`SMC_FVG_SCALP` was being used too broadly.

- `deterministicEngine.ts` could label a generic ranging setup as `SMC_FVG_SCALP` without proving an FVG existed.
- `SignalDetector.ts` labeled raw MTF liquidity sweeps as `SMC_FVG_SCALP`, even when the trigger was `MTF_SWEEP`, not `FVG_FILL`.
- The final FVG alignment gate used broad "near FVG" tolerance, which could pass visually distant entries on high-priced symbols.

## Change

- Ranging deterministic fallback now returns `MEAN_REVERSION` when there is no valid LTF `SCALPING` route.
- Raw MTF liquidity sweep signals are now `SCALPING`.
- Only `detectFvgFill()` keeps the `SMC_FVG_SCALP` label.
- `SMC_FVG_SCALP` final execution now requires `findAlignedFvgFill()`:
  - aligned active FVG direction (`BUY` needs bull FVG, `SELL` needs bear FVG)
  - price inside the FVG gap with small edge tolerance
  - at least `50%` fill

## Expected Effect

- Orders can still be generated by scalping logic, but they will be labeled honestly as `SCALPING` unless a real FVG fill exists.
- `SMC_FVG_SCALP` journal rows should now show `FVG_FILL bull/bear` evidence before execution.
- False confidence from strategy names should decrease; when a scalp is not FVG-backed, downstream gates and analytics will classify it as generic scalping/mean reversion.
