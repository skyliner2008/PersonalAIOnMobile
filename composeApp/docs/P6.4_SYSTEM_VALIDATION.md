# P6.4 — System Validation Harness

## Purpose

P6.4 provides a repeatable validation gate for the PersonalAIBot trading stack. It separates deterministic automated checks from manual/device/network acceptance checks.

## Automated validation

Run:

```text
:composeApp:testDebugUnitTest
:composeApp:compileDebugKotlinAndroid
```

`SystemValidationHarnessTest` verifies:

- safe RiskEngine PASS path
- daily loss limit blocks execution
- drawdown limit blocks execution
- failed strategy gate blocks execution
- unsafe MT5 order volume is rejected
- close-all requires explicit confirmation

Existing tests continue to cover Demo account costs, market pricing, Demo execution, MT5 risk snapshots, SMC/P3 fixture parity, indicator/signal parity, tool routing and tool lifecycle.

## Manual acceptance matrix

| Gate | Validation | Expected |
|---|---|---|
| G0 | Build + unit tests | PASS |
| G1 | App startup + Live READY | READY visible |
| G1 | Auto greeting | One greeting per Live lifecycle |
| G1 | Tool → AI response | Response after tool completion |
| G2 | Market/MTF/SMC signal | Valid, no NaN/Infinity |
| G3 | Backtest/robustness | Reproducible and coherent |
| G3 | Monte Carlo/permutation | Stable statistical evidence |
| G3 | Strategy Ranking/Risk Gate | PASS/HOLD behaves correctly |
| G4 | Demo execution | Risk-gated order + correct P/L |
| G4 | Restart persistence | Account/positions survive restart |
| G4 | Kill switch | Execution blocked immediately |
| G4 | Broker parity | Spread/commission/rebate/swap accounted once |
| G5 | MT5 Demo connection | Snapshot matches terminal |
| G5 | MT5 Demo execution | Order/position/deal reconciliation |
| G6 | LIVE safety | Live cannot bypass confirmation/risk gate |

## Failure injection

Before any live-money consideration, test:

- network loss/recovery
- Gemini timeout/429/session reset
- MT5 disconnect/no quote/market closed
- insufficient margin
- invalid volume
- missing SL
- excessive spread/slippage
- risk limit exceeded
- kill switch
- server-confirmation failure while changing DEMO/LIVE mode

Expected behavior is fail-safe: block or recover without silently enabling live execution.

## Evidence standard

A gate is PASS only when there is evidence from either automated test output or a recorded manual acceptance result. `BUILD SUCCESSFUL` alone does not prove end-to-end trading correctness.

## Live trading rule

G0–G5 must pass on MT5 Demo before enabling real-money/live execution. P6.4 does not authorize live trading by itself.
